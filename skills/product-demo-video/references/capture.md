# 录制一段产品交互

从已确认的场景出发，先核对「起始状态 → 用户操作 → 可见结果」。确认原型的入口、开始页面和所需权限。功能依赖本地服务或后端时，按项目已有的启动方式运行，并用独立的测试资料库、测试账号或示例数据走完整流程。用示例替代外部响应时，在画面标明「原型演示」「演示数据」或「AI 示例结果」等具体来源。

## 选择操作方式

- 录制**网页或本地原型**时，优先控制用户指定的浏览器或标签页。可用项目已有的浏览器自动化时，用它设置视口、执行交互并录屏。适合使用应用内浏览器时，通过其实际标签页操作。使用隔离浏览器配置可以把测试资料与日常会话分开。
- 录制**浏览器扩展或桌面应用**时，用能实际看到目标界面并完成交互的浏览器或电脑操作工具。需要展示扩展侧栏、系统文件选择或权限弹窗时，确认录到的是相应界面。优先后台操作，必须占用前台时先说明。
- 录制 **Figma 原型**时，先确认给定链接能打开可运行的原型呈现页，并验证目标交互确实已连线。设计文件包含多个功能时，先确定当前需求涉及的画面。

## Figma 状态演示

当设计帧齐全但目标交互尚未连线时，可以用前后状态制作标明「原型演示」的视频。先确认相关状态图、关键动作与结果的对应关系。把计划补出的行为写进当前幕的画面安排，得到确认后制作相应状态和动画。用户已有明确说明时沿用该说明。

核对列表项与详情的关系、展开后的内容去向、固定区与滚动区、分页和预填字段等当前幕实际涉及的行为。静态画面无法确定时，请用户补充这个具体细节。核对同一示例中的问题、关键词、结果数量、网站图标、来源列表、链接标题与实际打开的网页；数量和图标应符合产品定义，图标对应真实示例来源。原图的占位文案或无关品牌图标也属于这次核对范围。原图已有的设计问题可以按确认意见修正在视频素材中。

保存原始导出图、视频中实际采用的状态图和镜头时间点。业务专用的画面重建放在项目里。可用渲染器的 `shots` 按时点编排静帧或 PNG 序列。确认素材仍不足以表现结果时，再请用户补相关状态图、可运行的原型或本地录屏。

## 构图和动作

1. 按产品的自然比例设置视口。横版可用 1440 × 810 或更大的 16:9 视口。竖屏产品可保持竖屏录制，再使用左右并排版式。锁定窗口尺寸、设备像素比和自然缩放，原始素材保留完整可见区域。成片默认只展示一份产品画面，可先呈现全貌，再按已确认的构图沿同一画面推近或平移；保留辨认操作所需的入口、目标与结果。需要阅读下方内容时实际滚动。最终合成预留底部进度条区域。
2. 开始前留一点时间让观众辨认起始状态。按实际操作路径移动鼠标并执行动作，停留到结果可读。保存或更新可从结果卡、重新打开的记录或测试资料库复读确认。生成类演示核对输入、可见输出及其来源。
3. 保留原始录屏和关键时间点，至少记下动作发生与结果完整可见的时间。若原录屏自带清晰鼠标与点击圈，直接复用。否则可在渲染清单为点击添加 `clicks`，例如 `[{"at":1.25,"x":0.72,"y":0.38}]`。`at` 是剪辑后的输出秒数。`x`、`y` 从实际展示区左上角起算，分别除以展示区宽和高，范围为 0 到 1。
4. 点击前先核对真正触发动作的区域：按钮主体、左侧图标、箭头或独立关闭控件可能是不同目标。缩放、裁切或平移后，从实际导出的点击帧核对标记仍落在所需区域内，再检查动作后的可见结果。

## 交给剪辑

一个完整动作可交一段原始录屏。需要片头交代任务或片尾留时间看清结果时，可用静帧停留。无法直接操作原型时，可用用户提供的本地录屏走相同交付流程，先确认画面包含动作和结果，并处理账号、密钥与私人资料。交付前检查开头、动作触发前后及最后一帧，确认字幕和指针没有遮挡关键按钮或结果。
